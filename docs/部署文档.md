# 部署文档

本文说明如何把 DouyinLiveRecorder（含桌面端与 Web 管理端）部署到 Windows 电脑、Linux 服务器或 Docker 中。日常使用方法见 [运行文档](运行文档.md)。

## 1. 先选部署方式

| 场景 | 推荐方式 | 章节 |
|---|---|---|
| 自己的 Windows 电脑，想要窗口界面 | 桌面端（源码运行或打包成 exe） | 第 4 节 |
| 云服务器 / NAS / 家里常开的 Linux 主机，用浏览器管理 | Web 管理端 + systemd | 第 5 节 |
| 已经在用 Docker | Docker（自行构建镜像） | 第 6 节 |
| 只想和原版一样用命令行 | `python main.py` | 第 4.1 / 5.2 节 |

三种前端（命令行 `main.py`、桌面端 `gui.py`、Web 端 `web_server.py`）共用同一套录制引擎和同一份配置。**同一个程序目录下同一时间只运行其中一个**，否则会出现同一个直播间被录制两次。

## 2. 环境要求

| 依赖 | 要求 | 说明 |
|---|---|---|
| Python | 3.10 及以上 | 用打包好的 exe 时不需要 |
| ffmpeg | 较新版本即可 | 录制必需。缺失时命令行版会自动下载安装，桌面端会弹窗询问；Linux 建议手动安装 |
| Node.js | 建议当前 LTS 版本 | 部分平台的签名脚本需要。缺失时程序会尝试自动安装（Linux 下需要 root 权限） |
| 磁盘 | 视录制量而定 | 剩余空间低于阈值（默认 1 GB）时会停止录制 |
| 网络 | 能访问直播平台 | 录制海外平台需要代理，见 [运行文档](运行文档.md) 第 6 节 |

Python 依赖分为三组：

| 文件 | 用途 |
|---|---|
| `requirements.txt` | 录制核心与命令行，**必装** |
| `requirements-gui.txt` | 桌面端（PySide6） |
| `requirements-web.txt` | Web 管理端（FastAPI、uvicorn） |

## 3. 获取代码并安装依赖

```bash
git clone <你的仓库地址> DouyinLiveRecorder
cd DouyinLiveRecorder
git checkout gui            # 二次开发的代码在 gui 分支
```

### 3.1 使用 pip + 虚拟环境

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Linux / macOS
source .venv/bin/activate

pip install -U pip
pip install -r requirements.txt                 # 必装
pip install -r requirements-gui.txt             # 需要桌面端时
pip install -r requirements-web.txt             # 需要 Web 端时
```

国内网络慢可以加镜像源：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

### 3.2 使用 uv（可选）

```bash
uv sync                      # 只装核心
uv sync --extra gui          # 加装桌面端
uv sync --extra web          # 加装 Web 端
uv run web_server.py         # 用 uv 运行
```

### 3.3 安装 ffmpeg 与 Node.js

- **Windows**：可以跳过，命令行版启动时会自动下载安装，桌面端会弹窗询问是否安装；也可以手动安装后加入 `PATH`，或在程序目录下建 `ffmpeg` 文件夹并放入 `ffmpeg.exe`。
- **Ubuntu / Debian**：
  ```bash
  sudo apt update && sudo apt install -y ffmpeg
  curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash - && sudo apt install -y nodejs
  ```
- **CentOS / RHEL**：
  ```bash
  sudo yum install -y epel-release && sudo yum install -y ffmpeg
  curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash - && sudo yum install -y nodejs
  ```
- **macOS**：`brew install ffmpeg node`

检查是否装好：`ffmpeg -version` 和 `node -v` 都能输出版本号即可。

### 3.4 准备配置文件

首次运行时，如果 `config/config.ini` 不存在，程序会从 `config/config.ini.example` 复制一份并补全缺少的配置项，无需手动创建。要录制的直播间可以先写进 `config/URL_config.ini`（每行一个），也可以启动后在界面里添加。

## 4. Windows 桌面部署

### 4.1 源码运行

```powershell
# 桌面端（带控制台窗口，便于看报错）
python gui.py
# 桌面端（不显示控制台窗口）
pythonw gui.py
# 原版命令行
python main.py
```

关闭桌面端窗口时会询问"最小化到托盘"还是"退出程序"，可以勾选"记住我的选择"。退出时会先停止所有录制并保存文件，可能需要等待十几秒。

### 4.2 打包成 exe 分发（推荐：三端打包到同一个文件夹）

在开发机上执行：

```powershell
pip install -r requirements.txt -r requirements-gui.txt -r requirements-web.txt pyinstaller
python packaging/build_all.py --with-ffmpeg
```

- `--with-ffmpeg`：把项目根目录下的 `ffmpeg\` 文件夹一起打包进去，目标电脑不用再下载 ffmpeg。
- `--with-node`：同理，打包项目根目录下的 `node\` 文件夹。
- 两个参数都是可选的，不加时目标电脑首次运行会自动检测并安装。

产物在 `dist\DouyinLiveRecorder\`，把**整个文件夹**拷贝到目标电脑即可，目标电脑不需要安装 Python。目录结构：

```
DouyinLiveRecorder\
├── DouyinLiveRecorder.exe      命令行版（与 python main.py 相同）
├── DouyinLiveRecorderGUI.exe   桌面端
├── DouyinLiveRecorderWeb.exe   Web 管理端（支持 --host / --port / --password 参数）
├── _internal\                  三个程序共用的运行库，不要删除
├── config\config.ini.example   首次运行时自动生成 config.ini
├── ffmpeg\                     （使用 --with-ffmpeg 时）
├── docs\                       部署文档、运行文档
├── StopRecording.vbs           原版的强制结束脚本
└── index.html                  原版的 m3u8/flv 网页播放器
```

三个程序共用同一份配置和直播间列表，**同一时间只运行其中一个**。运行后会在同目录下生成 `config\config.ini`、`downloads\`、`logs\`、`backup_config\`。不含 ffmpeg 时整个文件夹约 90 MB，含 ffmpeg 约 260 MB。

只需要桌面端时，也可以执行 `python packaging/build_desktop.py`，产物在 `dist\DouyinLiveRecorderGUI\`。

### 4.3 开机自启

按 `Win + R` 输入 `shell:startup` 打开启动文件夹，放入 `DouyinLiveRecorderGUI.exe` 的快捷方式（源码运行则放入执行 `pythonw gui.py` 的快捷方式，"起始位置"填项目目录）。建议同时在关闭窗口时选择"最小化到托盘"。

### 4.4 在 Windows 上后台运行 Web 端

想在 Windows 主机上用浏览器（包括手机）管理时，可以用任务计划程序后台运行 Web 端：

1. 打开"任务计划程序" → "创建任务"。
2. "常规"：勾选"不管用户是否登录都要运行"。
3. "触发器"：新建 → "启动时"。
4. "操作"：新建 → 程序填 `<项目目录>\.venv\Scripts\pythonw.exe`，参数填 `web_server.py`，起始于填 `<项目目录>`。使用打包版时，程序填 `<打包目录>\DouyinLiveRecorderWeb.exe`，参数留空，起始于填 `<打包目录>`。
5. "设置"：取消"如果任务运行时间超过以下时间，停止任务"。

要让局域网其他设备访问，需要在配置里把监听地址改成 `0.0.0.0` 并设置访问密码（见 5.3 节），并在 Windows 防火墙放行对应端口。

## 5. Linux 服务器部署（Web 管理端）

### 5.1 安装

```bash
sudo mkdir -p /opt/DouyinLiveRecorder && sudo chown $USER /opt/DouyinLiveRecorder
git clone <你的仓库地址> /opt/DouyinLiveRecorder
cd /opt/DouyinLiveRecorder && git checkout gui
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-web.txt
```

再按 3.3 节安装 ffmpeg 和 Node.js。

### 5.2 先手动试运行

```bash
cd /opt/DouyinLiveRecorder
.venv/bin/python web_server.py --host 127.0.0.1 --port 8686
# 另开一个终端验证
curl http://127.0.0.1:8686/api/auth
# 输出 {"required":false,"authenticated":true} 说明服务正常
```

只想用原版命令行时运行 `.venv/bin/python main.py`。命令行版每 5 秒会清屏刷新状态，适合放在 `tmux` / `screen` 里运行，不适合用 systemd 托管；服务器上更推荐用 Web 端。

### 5.3 Web 端的监听地址与密码

Web 端的设置在 `config/config.ini` 的 `[Web]` 段：

```ini
[Web]
监听地址 = 127.0.0.1
端口 = 8686
访问密码 =
```

也可以用命令行参数或环境变量覆盖（优先级：命令行参数 > 环境变量 > config.ini）：

| 配置项 | 命令行参数 | 环境变量 |
|---|---|---|
| 监听地址 | `--host` | `DLR_WEB_HOST` |
| 端口 | `--port` | `DLR_WEB_PORT` |
| 访问密码 | `--password` | `DLR_WEB_PASSWORD` |

规则：

- 监听地址是 `127.0.0.1` / `localhost` 时只能本机访问，可以不设密码。
- 监听其他地址（如 `0.0.0.0`）时**必须设置访问密码**，否则程序拒绝启动，并提示"必须先设置访问密码"。
- 通过 Nginx 反向代理对外开放时，Web 端本身监听 `127.0.0.1` 不会强制要求密码，**但你仍然应该设置密码**，否则任何人都能访问。
- 登录状态保存在内存中，有效期 7 天；修改密码或重启服务后需要重新登录。

### 5.4 用 systemd 托管

创建运行用户（可选但推荐）：

```bash
sudo useradd -r -s /usr/sbin/nologin dlr
sudo chown -R dlr:dlr /opt/DouyinLiveRecorder
```

创建 `/etc/systemd/system/douyin-live-recorder.service`：

```ini
[Unit]
Description=DouyinLiveRecorder Web
After=network-online.target
Wants=network-online.target

[Service]
User=dlr
WorkingDirectory=/opt/DouyinLiveRecorder
ExecStart=/opt/DouyinLiveRecorder/.venv/bin/python web_server.py
Environment=DLR_WEB_PASSWORD=请改成你的密码
Restart=on-failure
RestartSec=10
# 停止时引擎会通知 ffmpeg 收尾，最多需要约 40 秒，避免被提前强杀导致文件损坏
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now douyin-live-recorder
sudo systemctl status douyin-live-recorder
journalctl -u douyin-live-recorder -f        # 查看输出
```

### 5.5 Nginx 反向代理与 HTTPS

页面的实时状态通过 WebSocket（`/ws/events`）推送，反向代理必须转发 WebSocket，否则页面左下角会一直显示"连接中断，重连中…"。

```nginx
server {
    listen 443 ssl;
    server_name rec.example.com;

    ssl_certificate     /etc/ssl/rec.example.com.pem;
    ssl_certificate_key /etc/ssl/rec.example.com.key;

    location /ws/ {
        proxy_pass http://127.0.0.1:8686;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }

    location / {
        proxy_pass http://127.0.0.1:8686;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 下载大录像文件时不缓冲
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

如果不用反向代理、直接对外开放端口，记得在防火墙放行端口（如 `sudo ufw allow 8686/tcp`），并且一定要设置访问密码。公网访问建议走 HTTPS，否则密码会明文传输。

## 6. Docker 部署

> **注意**：`docker-compose.yaml` 里默认的镜像 `ihmily/douyin-live-recorder:latest` 是上游原作者发布的，**不包含本次二次开发的桌面端和 Web 端**。要用 Web 端必须自行构建镜像。

### 6.1 构建并启动

把 `docker-compose.yaml` 改成下面这样（或另存为 `docker-compose.web.yaml`）：

```yaml
services:
  app:
    build: .
    image: douyin-live-recorder-gui:latest
    environment:
      - TERM=xterm-256color
      - MODE=web                       # web = Web 管理端；cli = 原版命令行
      - DLR_WEB_PASSWORD=请改成你的密码
    ports:
      - "8686:8686"
    tty: true
    stdin_open: true
    volumes:
      - ./config:/app/config
      - ./logs:/app/logs
      - ./backup_config:/app/backup_config
      - ./downloads:/app/downloads
    # 停止时给 ffmpeg 留出收尾时间，避免录像文件损坏
    stop_grace_period: 60s
    restart: always
```

```bash
docker compose up -d --build
docker compose logs -f
```

浏览器打开 `http://服务器IP:8686`，输入 `DLR_WEB_PASSWORD` 设置的密码登录。

### 6.2 容器相关说明

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MODE` | `cli` | `cli` 运行原版命令行，`web` 运行 Web 管理端 |
| `DLR_WEB_PORT` | `8686` | 容器内 Web 端口，修改后 `ports` 也要对应修改 |
| `DLR_WEB_PASSWORD` | 空 | Web 模式下必须设置（容器内监听 `0.0.0.0`） |

- 挂载的 `./config` 为空时，程序会自动生成默认配置。
- `MODE=cli` 时，如果 `URL_config.ini` 为空，程序会在终端里等待输入直播间地址，容器后台运行时请先把地址写进 `./config/URL_config.ini`；`MODE=web` 没有这个限制。
- `docker compose stop` 会发送 SIGTERM，程序会正常停止录制并保存文件；Docker 默认只等 10 秒，所以上面配置了 `stop_grace_period: 60s`。
- 容器时区已设置为 `Asia/Shanghai`，录像文件名中的时间是北京时间。

## 7. 目录、数据与环境变量

程序根目录默认是**启动脚本（或 exe）所在目录**。

| 路径 | 内容 | 是否需要备份 |
|---|---|---|
| `config/config.ini` | 全部配置（含 Cookie、账号密码、推送密钥） | 是，注意保密 |
| `config/URL_config.ini` | 直播间列表 | 是 |
| `config/config.ini.example` | 配置模板，随代码更新 | 否 |
| `downloads/` | 录像文件（可在配置中改到其他位置） | 视需要 |
| `logs/streamget.log` | 警告和错误日志，300 KB 轮转 | 否 |
| `logs/PlayURL.log` | 直播源地址（开启"记录直播源地址"后才有） | 否 |
| `backup_config/` | 配置文件改动后的自动备份，各保留最近 6 份 | 否 |

其他环境变量：

| 变量 | 说明 |
|---|---|
| `DLR_HOME` | 指定程序根目录（配置、录像、备份都放在这里），不设置时为程序所在目录 |
| `DLR_SKIP_AUTO_INSTALL` | 设为 `1` 时导入平台模块不自动安装 Node.js；桌面端和 Web 端默认已设置，并会在后台另行检测 |

## 8. 升级、迁移与同步上游

### 8.1 升级本项目

```bash
# 先停止程序（Web/systemd: sudo systemctl stop douyin-live-recorder）
git pull
.venv/bin/pip install -r requirements.txt -r requirements-web.txt
# 再启动程序
```

`config/config.ini` 和 `config/URL_config.ini` 不受 git 管理，升级不会覆盖；新版本新增的配置项会在启动时自动补进 `config.ini`。Docker 部署执行 `docker compose up -d --build` 重新构建即可。

### 8.2 迁移到另一台机器

拷贝 `config/` 目录（以及需要保留的 `downloads/`）到新机器的程序目录即可。如果在配置里填了自定义保存路径，迁移后注意修改为新机器上存在的路径。

### 8.3 同步上游原作者的更新

- 上游对 `src/spider.py`、`src/stream.py`（平台接口修复）的改动，一般可以直接合并。
- 上游对旧版 `main.py` 中各平台分支的改动，需要手动移植到 `recorder_core/platforms.py` 中对应的适配函数。
- 上游新增平台时，在 `recorder_core/platforms.py` 用 `@register(...)` 新增一个适配函数，并把域名加入 `SUPPORTED_HOSTS`（海外平台加入 `OVERSEAS_HOSTS`）。

## 9. 安全建议

- `config/config.ini` 里有 Cookie、平台账号密码和推送密钥，不要提交到 git，也不要发给别人。
- Web 端对外开放时一定要设置强密码，公网访问使用 HTTPS。
- Web 端可以修改全部配置，包括"录制完成后执行的自定义脚本"。**能登录 Web 端的人就能在服务器上执行命令**，请只把密码给信任的人，并用权限受限的用户运行服务（见 5.4 节）。
- Web 端的文件下载和删除只允许操作录像目录内的文件。

## 10. 部署后检查清单

- [ ] `ffmpeg -version`、`node -v` 能正常输出（桌面端可在"环境与关于"页查看）
- [ ] 访问 `http://<地址>:<端口>/api/auth` 返回 JSON（Web 端）
- [ ] 添加一个正在直播的直播间，状态在一个检测周期内变为"录制中"
- [ ] "录制文件"页能看到文件，大小在增长
- [ ] 停止程序后，录像文件能正常播放
- [ ] 需要推送时，在"设置 → 推送"保存后点击"发送测试推送"能收到消息
