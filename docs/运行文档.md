# 运行文档

本文说明程序部署好之后怎么使用：添加直播间、调整录制设置、配置代理/Cookie/推送、管理录像文件和排查问题。安装与部署见 [部署文档](部署文档.md)。

## 1. 三种运行方式

| 方式 | 启动命令 | 适合 |
|---|---|---|
| 桌面端 | `python gui.py`，或双击打包好的 `DouyinLiveRecorderGUI.exe` | 在自己电脑上用窗口操作 |
| Web 管理端 | `python web_server.py`，浏览器打开 `http://127.0.0.1:8686` | 服务器 / NAS，用浏览器或手机管理 |
| 命令行 | `python main.py` | 和原版完全一样，靠编辑配置文件操作 |

三者读写的是同一份 `config/config.ini` 和 `config/URL_config.ini`，可以随时换着用，但**同一时间只运行一个**。不管用哪种方式，直接用文本编辑器修改这两个文件也会在约 3 秒内自动生效。

## 2. 第一次使用

1. 启动程序。首次启动会自动生成 `config/config.ini`。
2. 桌面端会检查 ffmpeg 和 Node.js，缺失时弹窗询问是否自动安装；Web 端缺少 ffmpeg 时会在终端打印警告。可在"环境与关于"页确认状态。
3. 添加要录制的直播间（见第 3 节）。
4. 程序按"检测间隔"轮流检查每个直播间，主播开播后自动开始录制，下播后自动结束并保存。
5. 录像默认保存在程序目录下的 `downloads/`。

Web 端设置了访问密码时，打开页面会先要求登录；重启服务或修改密码后需要重新登录。

## 3. 管理直播间

### 3.1 添加

- **桌面端 / Web 端**：点"添加"，填直播间地址，可选画质和主播名称（留空会在首次检测时自动获取）。界面会提示识别出的平台，无法识别的地址不能添加。
- **批量导入**：点"批量导入"，每行一个，格式与 `URL_config.ini` 相同。
- **命令行**：编辑 `config/URL_config.ini`，每行一个。命令行版首次启动且文件为空时，会在终端里提示输入一个地址。

`URL_config.ini` 每行的格式：

```
[#][画质,]直播间地址[,主播: 名称]
```

示例：

```
https://live.douyin.com/745964462470
超清,https://www.huya.com/116
https://live.bilibili.com/21593109,主播: 某主播
#高清,https://www.douyu.com/xxxx,主播: 暂停中的主播
```

- 画质可选：原画、蓝光、超清、高清、标清、流畅。不写时使用设置里的"默认画质"。
- 行首加 `#` 表示暂停该直播间。
- 地址尽量用电脑网页端的直播间地址；抖音也支持 App 分享的短链接。
- 程序会自动去重、清理地址里多余的参数，无法识别的地址会被自动加上 `#`，首次检测成功后会自动补上 `主播: 名称`。

### 3.2 各种操作

| 操作 | 效果 | 命令行对应做法 |
|---|---|---|
| 暂停 | 停止监测；正在录制的会停止并保存文件 | 行首加 `#` |
| 恢复 | 重新开始监测 | 去掉行首的 `#` |
| 立即检测 | 不等检测间隔，马上检查一次 | 无 |
| 停止本场录制 | 停止当前录制并保存，**本场直播不再录制**，继续监测，主播下次开播时自动录制 | 无 |
| 编辑 | 修改地址、画质、名称 | 直接改那一行 |
| 删除 | 从列表移除；正在录制的会停止并保存文件 | 删除那一行 |
| 全部暂停 / 全部恢复 | 对所有直播间执行暂停 / 恢复 | 无 |
| 预览（Web 端） | 在浏览器里播放当前直播源。部分平台有防盗链或跨域限制，可能播不了，不影响录制 | 无 |
| 复制直播源（桌面端） | 复制当前直播源地址，可粘贴到 PotPlayer、VLC 等播放器 | 开启"记录直播源地址"后查看 `logs/PlayURL.log` |

### 3.3 状态说明

| 状态 | 含义 |
|---|---|
| 待检测 | 刚添加，还没检测过 |
| 检测中 | 正在请求直播平台 |
| 未开播 | 主播没在直播，"下次检测"列显示倒计时 |
| 录制中 | 正在录制，"已录时长"列实时更新 |
| 直播中(未录制) | 主播在直播但没录：开启了"只推送不录制"、点过"停止本场录制"或磁盘空间不足，原因见"备注"列 |
| 已暂停 | 已暂停监测 |
| 出错 | 获取直播信息失败，原因见"备注"列；会在下个检测周期自动重试 |

直播流正常结束后，程序会在 30 秒后再检查一次，避免主播短暂断流导致漏录；录制出错（如 ffmpeg 报错退出）时则在下一个检测周期重试。

## 4. 录制设置

在桌面端或 Web 端的"设置"页修改，保存后立即生效；也可以直接编辑 `config/config.ini`。下表是界面上的名称和 `config.ini` 里的键名对照，"默认"列是首次运行时从 `config.ini.example` 生成的值。

### 4.1 录制

| 界面名称 | config.ini 键名（[录制设置]） | 默认 | 说明 |
|---|---|---|---|
| 保存格式 | 视频保存格式ts\|mkv\|flv\|mp4\|mp3音频\|m4a音频 | ts | **推荐 ts**，异常中断时文件不容易损坏 |
| 默认画质 | 原画\|超清\|高清\|标清\|流畅 | 原画 | 直播间没单独设置画质时使用 |
| 同时检测的直播间数 | 同一时间访问网络的线程数 | 3 | 太大可能被平台封 IP；错误多时程序会自动调低 |
| 检测间隔(秒) | 循环时间(秒) | 300 | 每个直播间两次检测之间的间隔，实际会随机 ±5 秒 |
| 启动各直播间的间隔(秒) | 排队读取网址时间(秒) | 0 | 程序启动时逐个启动直播间的间隔，直播间很多时可以设几秒 |
| 分段录制 | 分段录制是否开启 | 是 | 开启后按"分段时长"切成多个文件 |
| 分段时长(秒) | 视频分段时间(秒) | 1800 | |
| 强制 https 拉流 | 是否强制启用https录制 | 否 | |
| 磁盘剩余空间阈值(GB) | 录制空间剩余阈值(gb) | 1.0 | 低于该值时停止全部录制。命令行版会退出；桌面端和 Web 端会暂停录制，空间恢复后继续 |
| 记录直播源地址 | 是否显示直播源地址 | 否 | 开启后把直播源地址写入 `logs/PlayURL.log` |

### 4.2 文件与后处理

| 界面名称 | config.ini 键名（[录制设置]） | 默认 | 说明 |
|---|---|---|---|
| 保存路径 | 直播保存路径(不填则默认) | 空 | 留空则保存到程序目录下的 `downloads/` |
| 按主播分文件夹 | 保存文件夹是否以作者区分 | 是 | |
| 按日期分文件夹 | 保存文件夹是否以时间区分 | 否 | |
| 按直播标题分文件夹 | 保存文件夹是否以标题区分 | 否 | |
| 文件名包含标题 | 保存文件名是否包含标题 | 否 | |
| 去除名称中的表情符号 | 是否去除名称中的表情符号 | 是 | |
| 录完自动转 mp4 | 录制完成后自动转为mp4格式 | 是 | 对 ts、flv 格式生效；停止录制时也会转换 |
| 转 mp4 时重编码为 h264 | mp4格式重新编码为h264 | 否 | 兼容性更好，但很耗 CPU |
| 转换后删除原文件 | 追加格式后删除原文件 | 是 | 转换成功后删除 ts / flv 原文件 |
| 生成时间字幕(srt) | 生成时间字幕文件 | 否 | 生成显示录制时刻的字幕；分段录制和音频录制时不生成 |
| 录完执行自定义脚本 | 是否录制完成后执行自定义脚本 | 否 | 见 4.4 节 |
| 自定义脚本命令 | 自定义脚本执行命令 | 空 | |

### 4.3 录像文件命名

默认（按主播分文件夹）：

```
<保存路径>/<平台>/<主播>/<主播>_<开始时间>.ts
例：downloads/虎牙直播/某主播/某主播_2026-11-23_20-11-45.ts
```

- 开启"文件名包含标题"：`<主播>_<标题>_<开始时间>.ts`
- 开启分段录制：`<主播>_<开始时间>_000.ts`、`_001.ts` ……
- 开启"按日期分文件夹"：在主播文件夹下再建一层 `2026-11-23/`

一些平台有特殊处理，不受"保存格式"影响：

- 猫耳FM、Look 直播只有音频，保存为 mp3。
- Shopee、花椒直播直接下载 FLV 流，保存为 flv。
- 抖音、TikTok 的直播源是 H.265 编码时，自动改用 ts 格式保存。

### 4.4 录完执行自定义脚本

一场直播**正常录制结束**后（手动停止的不执行），程序会在命令后追加参数再执行：

- 命令里包含 `python` 时：
  ```
  <你的命令> --record_name "序号1 主播名" --save_file_path "文件路径" --save_type TS --split_video_by_time False --converts_to_mp4 True
  ```
- 其他命令（如 bat、sh 脚本）时，按位置传参：
  ```
  <你的命令> "主播名" "文件路径" TS split_video_by_time:False converts_to_mp4:True
  ```

注意：开启分段录制时，文件路径里是 `_%03d` 这样的模板，需要脚本自己匹配同名前缀的分段文件。Linux 下脚本要有可执行权限（`chmod +x`），bash 脚本第一行要写 `#!/bin/bash`。

## 5. Cookie 与账号

在"设置 → Cookie"中按平台填写（对应 `config.ini` 的 `[Cookie]` 段）。

- **抖音建议填写 Cookie**，否则容易触发风控导致获取失败。获取方法：浏览器登录抖音网页版后打开任意直播间，按 F12 打开开发者工具 → 网络（Network）→ 刷新页面 → 点开任意请求，复制请求头里 `cookie` 的值。
- 其他平台一般留空，遇到需要登录或频繁获取失败时再填。

以下平台支持账号密码登录（"设置 → 账号"），登录后获取到的 Cookie / Token 会自动写回配置：SOOP、FlexTV、PopkonTV、TwitCasting。

## 6. 代理（录制海外平台）

TikTok、SOOP、PandaTV、WinkTV、FlexTV、PopkonTV、Twitch、LiveMe、Faceit 等海外平台需要能访问海外网络。有两种方式：

1. **系统全局代理 / 规则代理**：程序启动时会检测能否访问海外网站，状态显示在桌面端底部状态栏和"环境与关于"页。检测通过后无需其他设置。
2. **在程序里指定代理**（"设置 → 代理"）：

| 界面名称 | config.ini 键名 | 说明 |
|---|---|---|
| 使用代理 | 是否使用代理ip(是/否) | 总开关 |
| 代理地址 | 代理地址 | 如 `127.0.0.1:7890` |
| 走代理的平台关键字 | 使用代理录制的平台(逗号分隔) | 直播间地址包含这些关键字时才走代理，默认已包含常见海外平台 |
| 额外走代理的平台关键字 | 额外使用代理录制的平台(逗号分隔) | 即使关闭"使用代理"，地址包含这些关键字时也使用代理地址 |
| 跳过启动时的代理检测 | 是否跳过代理检测(是/否) | 确定网络能访问海外时开启，可加快启动 |

需要代理的平台既没检测到全局代理、也没配置代理地址时，状态会显示"出错"，备注为"网络异常…（需要代理）"。

## 7. 推送通知

在"设置 → 推送"中配置（对应 `[推送配置]` 段），保存后可以点"发送测试推送"检查是否配置正确。

| 渠道 | 需要填写 |
|---|---|
| 微信 | 微信(息知)接口 |
| 钉钉 | 钉钉 Webhook，可选 @手机号 / @全体 |
| TG | Telegram Bot Token 和 Chat ID |
| 邮箱 | SMTP 服务器、端口、是否 SSL、登录账号、密码/授权码、发件人、收件人 |
| BARK | Bark 接口，可选中断级别、铃声 |
| NTFY | ntfy 地址（如 `https://ntfy.sh/你的主题`），可选标签、邮箱 |
| PUSHPLUS | PushPlus Token |

- 可以同时勾选多个渠道。微信、钉钉、Bark、ntfy、PushPlus 的地址/Token 和邮箱的收件人可以用逗号填多个。
- "开播推送"默认开启，"关播推送"默认关闭。
- 推送内容可以自定义，支持占位符 `[直播间名称]`、`[时间]`，用 `\n` 换行。
- 开启"只推送不录制"后只发通知、不录制，主播在播期间按"只推送模式检测间隔"（默认 1800 秒）检查。

桌面端另外会在系统托盘弹出"开始录制""录制完成""录制出错""磁盘空间不足"通知，Web 端会在页面右下角提示。

## 8. 录像文件管理

- **桌面端"录制文件"页**：按时间倒序列出录像目录下的所有文件，可以搜索、打开、打开所在文件夹、转为 MP4、删除。双击直接用系统播放器打开。
- **Web 端"录制文件"页**：可以搜索、下载、转为 MP4、删除。
- 不分段录制时，正在录制的文件不能删除；分段录制时请不要删除最新的那个分段。
- 手动"转为 MP4"不会删除原文件。

## 9. 日志

| 位置 | 内容 |
|---|---|
| 桌面端 / Web 端"运行日志"页 | 最近的运行记录（开始录制、录制完成、推送结果、错误等），默认显示"信息及以上"，切到"全部"可看到每次检测的过程。保存在内存中，重启后清空 |
| `logs/streamget.log` | 警告和错误，写入文件，300 KB 自动轮转 |
| `logs/PlayURL.log` | 直播源地址（需开启"记录直播源地址"） |
| 命令行终端 | 命令行版每 5 秒刷新一次状态面板，显示监测数、录制中的直播间和已录时长 |

## 10. 停止程序

**任何方式都请正常停止**，程序会通知 ffmpeg 收尾并保存文件，可能需要十几秒；强制结束可能导致正在录制的文件损坏（ts 格式通常仍可播放）。

| 方式 | 正常停止 |
|---|---|
| 桌面端 | 托盘菜单"退出"，或关闭窗口时选"退出程序" |
| Web 端（前台运行） | 在终端按 `Ctrl + C` |
| Web 端（systemd） | `sudo systemctl stop douyin-live-recorder` |
| 命令行 | 在终端按 `Ctrl + C` |
| Docker | `docker compose stop` |

`StopRecording.vbs` 是原版提供的强制结束脚本，会直接结束 ffmpeg 进程，只在程序无响应时使用。

## 11. 常见问题

**状态一直是"出错"，备注"直播间信息获取失败"**
- 抖音：先填写抖音 Cookie（第 5 节）。
- 地址不对：换成电脑网页端的直播间地址再试。
- 被平台限制：把"检测间隔"调大，"同时检测的直播间数"调小。
- 平台改了接口：查看 `logs/streamget.log` 里的报错，关注上游项目是否已修复。

**海外平台显示"需要代理"**：见第 6 节。

**录制中但文件很小或录了一会儿就结束**：多为网络不稳定或直播源中断。流正常结束时程序会在 30 秒后重新检测，如果仍在直播会继续录制（生成新文件）；ffmpeg 报错时在下一个检测周期重试。可在"运行日志"页查看 ffmpeg 的报错，必要时把"检测间隔"调小。

**桌面端提示"程序已经在运行中"**：桌面端已经在后台运行，请在系统托盘找到图标。如果确认没有在运行（例如之前异常退出），重新启动一次即可。

**Web 页面左下角一直显示"连接中断，重连中…"**：页面能打开但实时状态不更新，通常是反向代理没有转发 WebSocket，见部署文档 5.5 节。

**Web 端登录后过一段时间要重新登录**：登录有效期 7 天；重启 Web 服务或修改访问密码后也需要重新登录。

**Web 端启动时提示"必须先设置访问密码"**：监听地址不是本机地址时必须设置密码，见部署文档 5.3 节。

**端口被占用**：在 `config.ini` 的 `[Web]` 段修改端口，或启动时加 `--port 8687`。

**改了 config.ini 没生效**：程序约每 3 秒检查一次文件变化；如果同时在界面里有未保存的修改，界面上的设置页不会自动刷新，点"还原"即可看到文件里的最新值。

**磁盘满了**：低于"磁盘剩余空间阈值"后会停止录制。清理空间后，桌面端和 Web 端会自动恢复录制；命令行版会退出，需要重新启动。
